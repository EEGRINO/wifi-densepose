================================================================================
  RuView / Wi-Fi DensePose — руководство для разработчиков (RU)
  Репозиторий: wifidensepose1 (ESP32-S3 + laptop_server + static/map3d.html)
================================================================================

Документ описывает цепочку данных, физику CSI, нейромодель (upstream RuView),
инференс, обучение и источники моделей/данных по состоянию кода (firmware/,
laptop_server/nn_pipeline.py).


────────────────────────────────────────────────────────────────────────────────
1. НАЗНАЧЕНИЕ СИСТЕМЫ
────────────────────────────────────────────────────────────────────────────────

• Контур «радиовидения»: ESP32 принимает Wi-Fi кадры и измеряет CSI (Channel
  State Information); по UDP на ПК передаётся компактное представление канала;
  процесс nn_pipeline.py нормализует вектор, умножает на обученную матрицу позы,
  опционально классифицирует активность и рассылает JSON клиентам WebSocket.

• Браузер (static/map3d.html) визуализирует:
  - «тепловую» сетку 8×8 по 64 признакам (поля viz.heights / heights),
  - 3D-сцену со скелетом (манекен по классу активности ± подмес выхода модели),
  - вероятности активности, vitals (эвристики), карту комнаты и т.д.

• Это НЕ система точной метрической локализации «как GPS/UWB»: положение и поза
  выводятся как результат обученного отображения CSI → пространство признаков /
  классы. Геометрия сцены в Three.js задаётся шаблонами и масштабом интерфейса.


────────────────────────────────────────────────────────────────────────────────
2. КАК Wi-Fi СВЯЗАН С ЛЮДЬМИ И «ПОЛОЖЕНИЕМ» (CSI)
────────────────────────────────────────────────────────────────────────────────

2.1. Что такое CSI
• В Wi-Fi 802.11n/ac приёмник оценивает канал связи между передатчиком и
  приёмником для эквализации (равномерной подстройки под искажения среды).
• CSI — набор комплексных коэффициентов по поднесущим OFDM (частотным «бинам»).
  Каждая поднесущая описывает, как сигнал искажается на этой частоте.

2.2. Почему меняется при присутствии человека
• Электромагнитные волны отражаются от стен, мебели и тела; траектории
  многолучевые (direct path + reflections).
• Движение грудной клетки (дыхание), смещение конечностей и перемещение человека
  меняют интерференционную картину на антенне приёмника → меняются амплитуды и
  фазы коэффициентов CSI.

2.3. Что именно использует прошивка в этом проекте
• В firmware/src/ruview_csi.cpp callback wifi_csi_info_t получает сырое тело
  CSI (буфер байтов). Из каждой пары (int8 re, int8 im) извлекается модуль
  sqrt(re²+im²) → до RUVIEW_SC_MAX=64 амплитуд (см. extractAmplitudes).

2.4. Ограничения интерпретации
• Профиль CSI зависит от: канала роутера, полосы (рекомендуется 20 МГц),
  режима 802.11, уровня фонового трафика, положения ESP относительно AP и человека.
• Один вектор из 64 чисел не даёт однозначных координат X,Y,Z «облака точки»
  без модели, обученной на вашей комнате или синтетике. Система опирается на
  статистические закономерности: класс активности, грубый скелет в признаковом
  пространстве, эвристики vitals.


────────────────────────────────────────────────────────────────────────────────
3. АРХИТЕКТУРА ПОТОКА ДАННЫХ
────────────────────────────────────────────────────────────────────────────────

  [ESP32-S3]  esp_wifi_set_csi(true) → CSI callback
       │
       ├─► Извлечение 64 амплитуд; UDP пакет RUV1 + float[] (см. ruview_csi.cpp)
       │
       └─► Порт задаётся в конфиге (server_port; дефолт в коде 5555 — см.
           ruview_shared.h RUVIEW_UDP_PORT_DEFAULT). nn_pipeline слушает
           ОБА порта: 8080 и 5555 (см. комментарий в nn_pipeline.py).

  [ПК] nn_pipeline.py
       │
       ├─► UDP recv → parse_ruview_packet() → нормализация max(|h|)
       ├─► skeleton = h_norm @ W   с формой W ∈ ℝ^(64×32), выход 32 числа
       │      (интерпретируются как 16 точек × (x,y) в признаковом пространстве)
       ├─► Опционально: активность (CalibrationManager), blend прототипов зон,
       │      vitals, карта комнаты
       └─► WebSocket :8765 → JSON в браузер

  [Браузер] map3d.html подключается к ws://<host>:8765/, рисует CSI-бары и 3D.


────────────────────────────────────────────────────────────────────────────────
4. НЕЙРОМОДЕЛЬ И ФАЙЛЫ ВЕСОВ (upstream RuView + использование в nn_pipeline)
────────────────────────────────────────────────────────────────────────────────

4.1. Что за модель в экосистеме RuView
• Семейство весов в каталоге laptop_server/models/ соответствует проекту
  RuView / wifi sensing на Hugging Face (описание — models/README.md). Имя
  набора в config.json: «wifi-densepose-csi-embedding».

• Тип и архитектура (models/config.json):
  - model_type: «sona-lora» — базовый энкодер CSI с адаптерами LoRA (fine-tune).
  - architecture: «csi-encoder-8-64-128» — штатная цепочка признаков: входное
    измерение → скрытый слой 64 → эмбеддинг 128 измерений (в документации RuView
    для EDGE-пайплайна часто подаётся агрегированный вектор из 8 CSI-признаков).
  - custom.embeddingDim: 128 — размер контрастивного эмбеддинга после обучения.
  - custom.quantizationBits: 4 — квантование весов для компактных .bin (например
    model-q4.bin ~8 KB).

• Обучение upstream (метаданные config.json):
  - Контрастивное / триплетное обучение на большом числе кадров CSI (порядка
    десятков тысяч frames и сотен тысяч триплетов — см. totalFrames, totalTriplets).
  - LoRA: rank 8, alpha 16, dropout 0.05; целевые модули «encoder» и «task_heads».

• Задачи полной модели RuView (из README семейства моделей): помимо эмбеддинга
  предполагаются отдельные «головы» — presence (присутствие), activity (тип
  активности), vitals (дыхание/пульс и т.п.). Это описание полного стека;
  конкретный набор слоёв в ONNX/PyTorch в данном репозитории как отдельный
  граф не воспроизводится — используются готовые бинарники float32.

4.2. Что именно делает nn_pipeline.py с model-q4.bin
• Файл laptop_server/models/model-q4.bin читается как плоский массив float32
  (load_ml_model в nn_pipeline.py).

• Первые 64×32 элементов интерпретируются как матрица W ∈ ℝ^(64×32). После
  max-abs нормализации вектора CSI h ∈ ℝ^64 вычисляется y = h @ W → 32 числа,
  которые клиент трактует как условный «скелет» (16 ключевых точек × 2 координаты
  в признаковом пространстве, не обязательно метры в мире).

• То есть в этом демо-пайплайне из полного RuView-графа используется эквивалент
  одного линейного слоя (или вырезанный блок весов), сопоставленный размерности
  входа прошивки (64 амплитуды). Полный прогон энкодера 8→64→128 на ПК в коде
  отдельно не вызывается — упрощение для низкой задержки и простой зависимости.

• Альтернативы того же интерфейса: model-q2.bin / model-q8.bin (другая степень
  квантования); полный энкодер может храниться как model.safetensors в том же
  стиле репозитория RuView — см. таблицу файлов в models/README.md.

4.3. Модели, которые НЕ из RuView upstream (обучаются локально)
• Классификатор активности — взвешенный МНК → activity_model.npz (не глубокая
  нейросеть, линейный softmax-классификатор по расширенному вектору признаков).

• Модель зон тела — МНК → W_limb в limb_calib.npz.

• Поза с камеры — МНК lstsq → camera_pose_W.npz (подмена матрицы W).

Эти три блока дополняют или заменяют части поведения системы независимо от
архитектуры sona-lora в model-q4.bin.


────────────────────────────────────────────────────────────────────────────────
5. ПРОШИВКА (firmware): CSI И UDP
────────────────────────────────────────────────────────────────────────────────

Файлы: firmware/src/ruview_csi.cpp, firmware/include/ruview_shared.h

• RUVIEW_UDP_MAGIC "RUV1", до 64 поднесущих RUVIEW_SC_MAX.

• ruviewCsiBegin(): esp_wifi_set_csi_config (LLTF, HT-LTF и т.д.), регистрация
  CSI RX callback.

• ruviewStreamTask:
  - По свежему кадру CSI считаются амплитуды g_amp[].
  - Опционально baseline (вычитание фона) для отображения на WebSocket модуля;
    на UDP в sendUdpPacked передаются сырое g_amp (не disp — см. строку вызова
    sendUdpPacked(g_amp, ...) в текущей версии файла).
  - UDP не реже ~100 Гц по таймеру (lastUdp >= 10 ms).
  - Дополнительно может отправляться формат ADR (magic 0xC5110001) для других
    совместимых серверов.

Разработчику: при изменении формата пакета обязательно синхронизировать
parse_ruview_packet() на стороне Python.


────────────────────────────────────────────────────────────────────────────────
6. СЕРВЕР: nn_pipeline.py — ПАРСИНГ И ИНФЕРЕНС ПОЗЫ
────────────────────────────────────────────────────────────────────────────────

6.1. Разбор UDP (parse_ruview_packet)
• Ищется маркер RUV1; далее ts (uint32 LE), RSSI (int8), N (uint16), N×float32.
• Fallback: 64 байта как амплитуды (старая прошивка).
• inp ∈ ℝ^64 → norm = inp / max(|inp|) — Max-abs нормализация кадра.

6.2. Позовая «голова» (bundled model)
• MODEL_PATH по умолчанию laptop_server/models/model-q4.bin.
• Файл читается как массив float32; первые 64×32 весов трактуются как матрица W.
• Инференс: skeleton = norm @ W (матричное умножение 1×64 на 64×32).

6.3. Альтернатива: камера + МНК (camera_pose_W.npz)
• CameraPoseCalibrationManager собирает пары (norm(heights), skeleton_32 от
  фронтенда/MediaPipe). Обучение: numpy.linalg.lstsq(X, Y) → W размера (64,32).
• Сохранение в models/camera_pose_W.npz; при старте подменяет _W_MATRIX.
• Откат: revert к весам из model-q*.bin (копия _W_MATRIX_BIN).

6.4. Прототипы позы по зонам конечностей
• LimbCalibrationManager хранит сэмплы CSI по зонам head, r_arm, …
• recompute_pose_prototypes(): для каждого сэмпла norm @ W, усреднение →
  pose_proto[zone]; глобальное среднее pose_proto_global.
• apply_limb_pose_prototype_blend(): сдвигает 32-D выход базовой матрицы в
  сторону взвешенной комбинации (прототип_зоны − глобальное среднее), с ограничением
  нормы смещения (переменные RUVIEW_LIMB_POSE_ALPHA, RUVIEW_LIMB_POSE_MAX_BLEND).

6.5. Основной ESP при нескольких датчиках
• CSI_PRIMARY_IP или «липкий» первый IP — для записи калибровок, vitals, карты.
• Два ESP: CSI_DUAL_ACTIVITY_FUSION — усреднение или max вероятностей классов
  по двум синхронным кадрам (окно CSI_PAIR_MAX_DT).


────────────────────────────────────────────────────────────────────────────────
7. КЛАССИФИКАЦИЯ АКТИВНОСТИ (CalibrationManager)
────────────────────────────────────────────────────────────────────────────────

• Классы: empty, sleeping, sitting, standing, walking (ACTIVITY_LABELS).
• Сбор данных: во время записи с UX приходят кадры heights (уже нормированные в
  пайплайне при добавлении — см. add_sample), метка класса и число людей.
• Признаки (ACTIVITY_USE_EXTENDED_FEATS по умолчанию вкл.): вектор 64 CSI +
  4 вспомогательных (логарифм отношения верх/низ сетки 8×8, масштабированное std,
  разность верх/низ, энтропия распределения энергии) → итого 68 + bias.
• Обучение: one-hot по классам, взвешенный МНК (баланс классов через веса строк),
  отдельная регрессия W_ppl для числа людей.
• Инференс: softmax(logits), опциональный сдвиг логита standing
  (RUVIEW_ACTIVITY_STANDING_LOGIT_BIAS), затем _sharpen_sitting_standing_probs
  для схлопывания близких вероятностей sitting/standing (RUVIEW_ACTIVITY_SIT_STAND_GAP).
• Сохранение: models/activity_model.npz.


────────────────────────────────────────────────────────────────────────────────
8. КАЛИБРОВКА ЗОН ТЕЛА (LimbCalibrationManager)
────────────────────────────────────────────────────────────────────────────────

• Шесть зон LIMB_KEYS; пользователь двигает выбранную зону, сервер накапливает
  векторы CSI длиной 64 (сырые значения кадра до пост-обработки, см. add_sample).
• train_limb_net(): МНК Xb @ W ≈ Y с one-hot по зонам → W_limb (65×6), на инференсе
  softmax.
• Без обученной сети можно использовать сходство с центроидами (frame_scores).

Файл: models/limb_calib.npz (сэмплы, W_limb, прототипы позы).


────────────────────────────────────────────────────────────────────────────────
9. ОТКУДА БЕРЁТСЯ БАЗОВАЯ МОДЕЛЬ И «ДАТАСЕТЫ»
────────────────────────────────────────────────────────────────────────────────

9.1. model-q4.bin и семейство RuView (upstream)
• Подробное описание архитектуры нейромодели (sona-lora, энкодер, LoRA, квантование)
  — в разделе 4; здесь — источники файлов и данных.
• В каталоге laptop_server/models/ лежат артефакты в духе RuView / Hugging Face
  (см. models/README.md, config.json): контрастивное обучение энкодера CSI,
  квантование 4-bit, входная размерность и метаданные обучения описаны в README.
• Полный цикл обучения энкодера в этом репозитории как скрипт не дублируется —
  веса поставляются готовыми; проект использует вырезанную линейную часть 64→32
  из бинарника как «позовую матрицу» для демо.

9.2. Локальные датасеты (то, что реально генерируется на месте)
• activity_model.npz — записи активности из UI `map3d.html` во время сессии записи.
• limb_calib.npz — записи «зарядки» по зонам тела (голова, руки, ноги, торс).
• camera_pose_W.npz — результат обучения МНК по парам CSI+скелет с камеры
  (camera_calib.html + MediaPipe).

9.3. Конкретные форматы файлов (типы, ключи, размерности)

Общее: локальные «датасеты» хранятся в формате NumPy **.npz** (ZIP с несколькими
массивами `.npy` внутри). Чтение: `numpy.load(path, allow_pickle=False)` —
pickle в этих файлах не используется для данных.

──────── activity_model.npz (models/activity_model.npz)
• samp_<класс> — массив float32 формы (N, 64): по одной строке на каждый кадр,
  записанный во время записи класса <класс>. Имена ключей совпадают с
  ACTIVITY_LABELS в nn_pipeline.py: samp_empty, samp_sleeping, samp_sitting,
  samp_standing, samp_walking. Пустой класс — массив формы (0, 64).
• ppl_<класс> — скаляр (0-D массив), сохранённое число людей в комнате для этого
  класса (на последнюю запись сценария).
• W_act — после обучения train(): float32, форма (D_in, N_ACT), где N_ACT=5.
  D_in = 69 при включённых расширенных признаках (64 CSI + 4 aux + bias в МНК
  задаётся отдельным столбцом единиц — в сохранённой матрице последняя строка
  соответствует bias для каждого класса вместе с признаками в строках 0…D_in-2).
  Фактически в коде Xb = [X | ones], а W_act имеет строки под размерность hb:
  при расширенном входе признаковая часть X имеет 68 столбцов (64+4), плюс bias —
  итого shape[0] для W_act равен 69. Устаревший формат без aux: (65, N_ACT)
  = 64+bias на класс.
• W_ppl — float32, форма (D_in, 1): те же D_in строк регрессии «число людей».

Примечание: строки samp_* хранят те же нормированные heights (0…1 по max-abs),
  что попадают в add_sample во время записи (как в потоке после parse).

──────── limb_calib.npz (models/limb_calib.npz)
• samp_<зона> — float32 (N, 64) для зон head, r_arm, l_arm, r_leg, l_leg, torso.
  После записи с камеры в зону могут попадать уже max-нормированные векторы (см.
  append_batch_for_limb).
• W_limb — после train_limb_net(): float32 (65, 6): 64 входа + bias, 6 классов зон;
  на инференсе softmax(h @ W_limb).
• pose_proto_global — float32 (32,), среднее по всем norm(h)@W по калибровке.
• pose_proto_<зона> — float32 (32,) для каждой зоны с ненулевыми сэмплами.

──────── camera_pose_W.npz (models/camera_pose_W.npz)
• W — float32 (64, 32): матрица МНК X→Y, где строки X — max-norm CSI [0,1]^64,
  строки Y — скелет MediaPipe как 32 числа в порядке фронтенда.
• n_samples — целое число пар, участвовавших в последнем успешном train().

──────── Бинарные веса позы (не табличный «датасет», а экспорт модели)
• model-q2.bin / model-q4.bin / model-q8.bin — поток чисел float32 (после
  распаковки квантования в рабочий вид при загрузке в коде читается как float32).
  nn_pipeline использует первые 64×32 элементов как матрицу W. Размер файла и
  полный состав весов задаются upstream-сборкой RuView.

──────── model.rvf.jsonl (рядом с моделями в models/)
• Текстовый поток JSON Lines: первая строка metadata (имя модели, архитектура,
  счётчики кадров/триплетов при обучении), далее служебные записи type=encoder,
  lora, ewc, quantization. Это описание артефакта, а не размеченный датасет кадров.

──────── Потоковый формат «пары для обучения» (WebSocket → nn_pipeline)
• camera_pose_batch: JSON с полем samples — массив объектов
  { "heights" или "csi": [64 чисел], "skeleton": [32 числа] } (числа float).
• limb_zone / skip_camera_pose — дополнительные поля батча для зон (см. handle_cmd).

──────── Бинарный кадр CSI по UDP (сырой вход, не NPZ)
• См. раздел 6.1 / прошивку: пакет с префиксом RUV1 и массивом float32 длиной N
  (обычно 64). Это не файл датасета, а протокол онлайн-сбора; записанные в NPZ
  строки samp_* — уже разобранные и нормированные представления кадра.

──────── Датасеты upstream-обучения RuView
• В репозиторий не включены исходные таблицы кадров CSI (десятки тысяч frames,
  триплеты — см. config.json). Они собирались при обучении семейства моделей на
  стороне RuView; для повторного обучения энкодера нужны их внутренние пайплайны
  или выгрузка с Hugging Face, а не только .npz этого проекта.

Иными словами: «глобальный» prior на позу — из bundled model-q*.bin; адаптация
под комнату и пользователя — через перечисленные NPZ и переменные окружения.
Локальный разработчик работает с **NPZ + JSON батчами**; бинарник позы —
**сырой float32 blob**.


────────────────────────────────────────────────────────────────────────────────
10. VITALS И КАРТА КОМНАТЫ (эвристики в nn_pipeline.py)
────────────────────────────────────────────────────────────────────────────────

• Vitals: буфер motion/энергии по времени; через нормализацию, сглаживание и
  подсчёт пересечений нуля оцениваются respiration и heart_rate в разумных диапазонах.
  Это инженерная оценка для демо, не медицинский прибор.

• Карта комнаты: онлайн Welford mean/variance по 64 измерениям; комбинация
  среднего и низкой дисперсии интерпретируется как «статичные отражатели»
  (scores для UI).

13. ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ (выборочно)

CSI_PRIMARY_IP              — фиксировать «основной» ESP для калибровок/vitals.

14. ДИАГНОСТИКА
────────────────────────────────────────────────────────────────────────────────

• «Есть UDP, нет картинки в браузере»: проверить WebSocket :8765 и клиентов;

• Расхождение портов: ESP по умолчанию часто 5555; nn_pipeline слушает 8080 и 5555.


────────────────────────────────────────────────────────────────────────────────
15. ИТОГ: КАК «Wi-Fi ОПРЕДЕЛЯЕТ ПОЛОЖЕНИЕ»
────────────────────────────────────────────────────────────────────────────────

В терминах этого проекта:

1) Измеряется не координата в метрах, а вектор состояния канала (амплитуды CSI).

2) Обученное отображение (матрица W и/или камерная МНК) переводит этот вектор в
   32 числа, которые UI трактует как деформируемый «скелет» в признаковом пространстве.

3) Класс активности и зона тела — отдельные линейные (или центроидные) модели,
   обученные на данных ВАШЕЙ комнаты.

4) Точность ограничена средой; для научно-метрической локализации нужны калибровка,
   несколько приёмников, другие модели и часто синхронизация с эталонной системой.
