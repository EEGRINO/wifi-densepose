================================================================================
  Запуск nn_pipeline.py и map3d.html (WiFi DensePose / RuView)
================================================================================

Каталог с кодом сервера:  laptop_server/

Требуется Python 3 с зависимостями из laptop_server/requirements.txt
(удобно использовать виртуальное окружение venv внутри laptop_server).


--------------------------------------------------------------------------------
1. Активация окружения (Linux / macOS)
--------------------------------------------------------------------------------

  cd laptop_server

  Bash / zsh:
    source venv/bin/activate

  Fish:
    source venv/bin/activate.fish

  Либо без активации, явно интерпретатором:
    venv/bin/python3 nn_pipeline.py


--------------------------------------------------------------------------------
2. Запуск nn_pipeline.py
--------------------------------------------------------------------------------

  Из каталога laptop_server:

    python3 nn_pipeline.py

  Что поднимается:
    • UDP 0.0.0.0:8080 и 0.0.0.0:5555  — приём пакетов CSI от ESP32 (формат RUV1)
    • WebSocket 0.0.0.0:8765           — поток данных в браузер (map3d и др.)

  На ESP в настройках укажите IP этого компьютера и порт UDP 8080 или 5555
  (оба порта слушаются одновременно).

  Если порт 8765 занят:
    fuser -k 8765/tcp
    или завершите старый процесс nn_pipeline.


--------------------------------------------------------------------------------
3. Запуск веб-страницы map3d.html
--------------------------------------------------------------------------------

  nn_pipeline НЕ отдаёт HTML — страница открывается через простой HTTP-сервер.

  Второй терминал:

    cd laptop_server/static
    python3 -m http.server 8000

  Браузер (на том же компьютере):

    http://127.0.0.1:8000/map3d.html

  Важно: WebSocket в map3d подключается к ws://<hostname>:8765/
  Поэтому страницу лучше открывать с того же хоста, что и nn_pipeline
  (localhost → localhost). Если открываете с другого устройства в сети —
  подставьте IP ноутбука в адрес страницы и убедитесь, что файрвол пускает
  порты 8000 и 8765.

  Дополнительно из того же static:
    camera_calib.html   — калибровка позы с камерой + CSI
    calibration_guide.html


--------------------------------------------------------------------------------
4. Альтернатива: ruview_gateway.py
--------------------------------------------------------------------------------

  Можно поднять шлюз, который сам отдаёт static на :8080 (см. справку в файле).
  Для полного пайплайна с моделью позы и калибровками обычно используют именно
  nn_pipeline.py, как выше.


--------------------------------------------------------------------------------
5. Установка зависимостей (если venv ещё не настроен)
--------------------------------------------------------------------------------

  cd laptop_server
  python3 -m venv venv
  source venv/bin/activate
  pip install -r requirements.txt


--------------------------------------------------------------------------------
6. Краткий чеклист «не работает»
--------------------------------------------------------------------------------

  • В шапке map3d нет «live» у WebSocket — не запущен nn_pipeline или порт 8765 занят.
  • Есть «live», но красная надпись про CSI — WebSocket есть, но на ПК НЕ приходят
    UDP-пакеты от ESP. Пинг до ESP не гарантирует UDP: проверьте в веб-интерфейсе ESP
    IP ноутбука и порт 8080 или 5555. В логе nn_pipeline при успешном приёме появятся
    строки «📦 Первый пакет с порта …» и раз в 30 с «📊 UDP:…».
    Файрвол Linux:  sudo ufw allow 8080/udp   и   sudo ufw allow 5555/udp
  • Нет полос CSI — нет UDP от ESP (проверьте IP/порт в прошивке, файрвол, Wi-Fi).
  • JSON.parse в консоли — на стороне nn_pipeline включена санитизация NaN; обновите
    скрипт с репозитория.

  Несколько ESP на одном UDP-порту: nn_pipeline различает отправителей по IP, калибровка
  активности/конечностей и vitals/карта комнаты идут только с «основного» источника.
  По умолчанию основным становится первый увиденный IP до перезапуска. Чтобы зафиксировать
  вручную:  CSI_PRIMARY_IP=192.168.31.131  python3 nn_pipeline.py

  Оценка активности (ходьба и т.д.) с двух ESP: при двух разных IP в окне времени
  CSI_PAIR_MAX_DT (сек, по умолчанию 0.12) вероятности softmax по каждому датчику
  объединяются (mean или max):  CSI_DUAL_FUSION_MODE=mean  или  max
  Отключить слияние:  CSI_DUAL_ACTIVITY_FUSION=0
